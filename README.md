# HoneyWise

A mead-making companion: recipe book, ingredient presets and saved grid views.

| Folder | What it is |
|---|---|
| `HoneyWise.Api/` | ASP.NET Core (.NET 10) API. MediatR handlers, raw Npgsql data access, JWT auth. |
| `HoneyWise.Migrations/` | Console app that creates and upgrades the Postgres database (DbUp). |
| `honey-wise-web/` | Angular 20 web app (Angular Material, AG Grid). |
| `scripts/` | Developer scripts. |

## Run it locally

**Prerequisites:**
- [.NET 10 SDK](https://dotnet.microsoft.com/download)
- [Node.js 24 LTS](https://nodejs.org)
- [Docker Desktop](https://www.docker.com/products/docker-desktop), running. Not needed if you bring your own Postgres; see [Using your own Postgres](#using-your-own-postgres).

**Then, from the repo root:**

```powershell
./scripts/dev.ps1        # Windows (PowerShell)
```
```bash
./scripts/dev.sh         # macOS / Linux
```

The script is safe to re-run; each step skips itself when there's nothing to do. It:
1. Creates `.env` from `.env.example`.
2. Starts Postgres in Docker.
3. Applies migrations and demo data.
4. Generates a local JWT signing secret.
5. Installs npm packages.
6. Starts everything. Press Ctrl+C to stop.

| What | Where |
|---|---|
| Web app | http://localhost:4200 |
| API + Swagger UI | http://localhost:20000/swagger |
| Demo login | `demo` / `HoneyWise123!` |
| Postgres (Docker) | `localhost:5433`, user `postgres`, password `honeywise-dev`, database `Mead_Tool` |

Pass `-SetupOnly` (PowerShell) or `--setup-only` (bash) to prepare everything without starting the apps. This is handy if you'd rather launch the API from your IDE.

### Using your own Postgres
Edit `.env` (it's git-ignored):
1. Set `USE_DOCKER_DB=false`.
2. Point the `POSTGRES_*` values at your server.

The script then skips Docker and migrates your database instead.

If you launch the API from your IDE rather than the script, it reads `HoneyWiseConnection` from `appsettings.Development.json`, which matches the Docker defaults. To use your own Postgres there, override it once:

```powershell
dotnet user-secrets set HoneyWiseConnection "Host=localhost;Port=5432;Username=...;Password=...;Database=Mead_Tool" --project HoneyWise.Api
```

### Starting over
`docker compose down -v` deletes the local database. The next script run rebuilds it from scratch.

## Database changes

Schema and reference data live in `HoneyWise.Migrations/Scripts/` as numbered SQL files. The migrator runs on every `dev` script start, in CI, and on every deploy. It applies any script it hasn't seen before and records it in the `schemaversions` table.

**To change the database:**
1. Add a new file with the next number, e.g. `0005_add_batch_table.sql`.
2. **Never edit a script that has already been merged.** It has already run against real databases and won't run again; write a new script instead.
3. Prefer `IF NOT EXISTS` / `ON CONFLICT DO NOTHING` so scripts are forgiving.
4. Run the `dev` script, or apply the scripts directly:
   ```bash
   dotnet run --project HoneyWise.Migrations -- --connection "Host=...;Database=Mead_Tool"
   ```

`HoneyWise.Migrations/SeedDev/` holds sample data for local development only. It runs on every start with `--seed-dev` and never in production, so keep it idempotent.

## Configuration and secrets

| Setting | Local dev | Production |
|---|---|---|
| `HoneyWiseConnection` | `.env` (via the dev script) or `appsettings.Development.json` | Environment variable |
| `JwtSettings:Secret` (≥ 32 bytes) | user-secrets, generated by the dev script | Environment variable `JwtSettings__Secret` |

**Never commit real credentials.** `.env` and `appsettings.*.local.json` are git-ignored.
